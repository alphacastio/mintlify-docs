The API uses standard HTTP status codes. Check the status code first.

<span id="error-response-format" style={{ scrollMarginTop: "8rem" }} />

## Error body formats

Most errors return a `message` field:

```json
{ "message": "Dataset 123 doesn't exist" }
```

There are other formats:

| Case | Body |
|---|---|
| A required field is missing | `message` can be an object that names the field: `{"message": {"name": "..."}}` |
| Some conflicts | `message`, plus `code` and `details` |
| Provider endpoints, and some other endpoints | `{"error": "..."}` |
| `401`, and some other errors | Plain text or HTML |

Do not assume that the body is JSON.

```python
import requests

response = requests.get(url, auth=(api_key, ""))

if not response.ok:
    try:
        body = response.json()
        detail = body.get("message") or body.get("error")
    except ValueError:
        detail = response.text
    raise RuntimeError(f"{response.status_code}: {detail}")
```

## 400 Bad request

The request has missing or invalid data. Common causes:

- A required field is missing.
- A [manifest](/uploading/manifest) is not correctly formatted.
- A new dataset receives an upload before its [columns are initialized](/uploading/overview#before-the-first-upload).
- `$filter` cannot be parsed or names a column that does not exist. Column names are case-sensitive.
- A download uses an unsupported `$` parameter, or uses `$top` and `$last` together.

## 401 Unauthorized

The key is missing or invalid. Most endpoints require Basic Auth, with the key as the username.

```bash
# Correct
curl -u YOUR_API_KEY: https://api.alphacast.io/repositories

# Incorrect: the key is in the password field
curl -u :YOUR_API_KEY https://api.alphacast.io/repositories
```

See [Authentication](/authentication).

## 402 Payment required

Your plan does not let you create or clone assets, such as datasets. See [pricing](https://www.alphacast.io/pricing).

```json
{ "message": "Your plan does not allow creating or cloning assets. Please upgrade your subscription." }
```

Downloads handle plan access differently. See [Plan access to data](/api/datasets/data#plan-access-to-data).

## 403 Forbidden

You do not have the permission that the action requires. Many dataset and repository actions also return `403` when the ID does not exist or you cannot access it. Check both the ID and your permission.

## 404 Not found

The resource does not exist or is not visible to you. Check the ID.

## 409 Conflict

The request conflicts with the current state. Common causes:

| `code` | Meaning |
|---|---|
| `repository_name_taken` | The account already has a repository with that name. |
| `dataset_name_taken` | The repository already has a dataset with that name. |
| `dataset_published_by_pipeline` | A pipeline still publishes to the dataset. |
| `dataset_has_series` | The dataset has series and cannot be deleted. |
| `dataset_has_consumers` | Pipelines read the dataset. You can [confirm the deletion](/api/datasets/delete). |
| `dataset_has_dependencies` | Other content still uses the dataset. |

Some `409` errors have no `code`.

## 413 Request too large

The request body is over 80 MB. Compress your CSV with gzip or split the upload.

## 429 Too many requests

On provider endpoints, this means that an external provider's limit was reached. Wait, then send fewer requests. For some providers you can [save your own key](/api/providers/list#save-a-provider-key).

## 500 Internal server error

Something failed on the server. Check your request against the endpoint page. If it is correct and the error continues, contact support. Include the endpoint and the time of the request.

<span id="503-service-unavailable" style={{ scrollMarginTop: "8rem" }} />

## 501, 502, and 503

| Status | Meaning |
|---|---|
| `501` | The provider does not support the operation. |
| `502` | The external provider or the provider service failed. Retry later. |
| `503` | The service is temporarily unavailable. For uploads, a response with `processId` means that processing may have started. [Check that process](/api/datasets/upload#check-an-upload-process) before you upload again. |

## 504 Gateway timeout

The request took too long. Ask for less data in one request: use `$filter`, `$select`, `$top`, or `$last` on [downloads](/api/datasets/data), or the provider's date parameters on [provider series](/api/providers/series). Before you repeat a `POST` or an upload, check whether it already succeeded.

## Failures that arrive with a success status

- **Uploads:** `201` means that the upload was accepted. Data errors appear later, when the process status is `Error`.
- **Downloads:** check that the file contains data. See [Plan access to data](/api/datasets/data#plan-access-to-data).

## Debugging checklist

1. Check the status code before you read the body.
2. Read `message` or `error`. See [error body formats](#error-body-formats).
3. Check authentication. `curl -v` shows the headers that you send, including your key, so do not share that output.
4. Check that your JSON is valid and that you send `Content-Type: application/json`.
5. Check IDs. [List repositories](/api/repositories/list) or [list datasets](/api/datasets/list).
6. Before you filter, check column names with [Get columns](/api/datasets/columns).
