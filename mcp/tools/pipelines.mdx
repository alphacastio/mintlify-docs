Thirteen tools for working with Alphacast pipelines from an MCP client. Seven only read. Six need write access: the four tools that change pipelines, plus `get_step_preview` and `get_step_data`, which can start runs.

Alphacast validates and runs a pipeline after each saved change. The tools don't wait for that run unless you ask them to. Use [`wait_pipeline_run`](#wait_pipeline_run) to check the result.

<Warning>
  A pipeline run can fetch external data and run output steps, such as publishing to a dataset.
</Warning>

Creating pipelines requires a [plan](https://www.alphacast.io/pricing) that can create content. You also need Write access to the repository. For what each step does, see [Pipeline steps](/steps/overview).

<Tip>
  When `repositoryId` is omitted from `create_pipeline` or `list_pipelines`, the server uses your default writable repository. Call `list_repositories` only when the pipeline belongs somewhere else.
</Tip>

## `list_pipelines`

List one page of pipelines in a repository.

<ParamField body="repositoryId" type="number">
  Repository ID. Omit to use your default writable repository.
</ParamField>

<ParamField body="limit" type="number" default="50">
  Pipelines per page, from 1 to 100.
</ParamField>

<ParamField body="afterId" type="number">
  Pagination cursor. Pass the `nextAfterId` from the previous page.
</ParamField>

Returns each pipeline's ID, name, repository ID and URL, plus `hasMore` and `nextAfterId`. When `hasMore` is `true`, the list is not complete.

**Example prompt**

> "List all the pipelines in my default repository."

---

## `get_pipeline`

Get a pipeline with its steps: type, order, configuration summary, output columns, validation status and a link to each step in the editor. It also summarizes the last finished run, including its run ID.

<ParamField body="pipelineId" type="number | string" required>
  Numeric pipeline ID, pipeline slug, or full Alphacast pipeline URL.
</ParamField>

Some validation errors depend on a run. They are marked `PENDING RUN` instead of `ERROR`. Validation does not tell you how an active run will end.

**Example prompt**

> "Show me pipeline 4821. What does each step do, and is anything broken?"

---

## `get_pipeline_run`

Get a specific run by ID, including status, timestamps, and per-step logs.

<ParamField body="pipelineId" type="number" required>
  Pipeline ID.
</ParamField>

<ParamField body="runId" type="number" required>
  Run ID (from the pipeline's run history).
</ParamField>

**Example prompt**

> "What happened in run 91722 of pipeline 4821? Did step 3 fail?"

---

## `wait_pipeline_run`

Block until a specific run reaches a terminal state (`completed`, `failed`, `cancelled`, or `skipped`) and return its status and logs. Use the run ID returned by `create_pipeline`, `add_pipeline_step` or `edit_pipeline_step`.

<ParamField body="pipelineId" type="number" required>
  Pipeline ID.
</ParamField>

<ParamField body="runId" type="number" required>
  Run ID to wait on.
</ParamField>

<ParamField body="timeoutSeconds" type="number" default="60">
  Maximum seconds to wait before returning `timeout`.
</ParamField>

A `timeout` does not mean the run failed: its outcome is still unknown. Wait again on the same run ID. Don't start another run.

**Example prompt**

> "Wait up to 2 minutes for run 91722 to finish and tell me how it ended."

## `get_step_data`

Read the last computed output of a step. Needs both `mcp:read` and `mcp:write`.

<Warning>
  This tool can start a run. For a Data Snapshot step in a pipeline that uses `fetch-yahoo` or `fetch-fred`, Alphacast can start a full pipeline run if the last run is more than 20 minutes old. That run can fetch external data and run publish steps. The tool does not wait for it, so the data returned may not include the refresh.
</Warning>

<ParamField body="pipelineId" type="number" required>
  Pipeline ID.
</ParamField>

<ParamField body="stepId" type="number" required>
  Step ID (from `get_pipeline`).
</ParamField>

<ParamField body="format" type="string" default="csv">
  `csv` or `json`.
</ParamField>

<ParamField body="limit" type="number">
  Return the last N rows, from 1 to 5000. The hosted server defaults to 100. A limited CSV read only works if the complete cached file is within 4 MiB.
</ParamField>

<ParamField body="outputMode" type="string" default="auto">
  Hosted: `auto` or `inline`, both return limited rows. Local without `limit`: `auto` returns small outputs in the response and saves large ones to a temporary file, `inline` can cut off long output, and `file` saves the full output.
</ParamField>

<ParamField body="maxInlineChars" type="number" default="50000">
  Character budget for the response, from 1000 to 500000.
</ParamField>

**Example prompt**

> "Get the CSV output of step 11 in pipeline 4821."

## `get_step_preview`

Run a preview up to a step and return its output as CSV. Use it to check data while you debug, for example right after editing a step. Needs `mcp:write`.

The tool cancels runs of the pipeline that are processing, starts a preview run and waits up to about 60 seconds. The run can fetch external data. It may also run earlier steps again, including output steps.

<ParamField body="pipelineId" type="number" required>
  Pipeline ID.
</ParamField>

<ParamField body="stepOrder" type="number" required>
  0-based order of the step to preview.
</ParamField>

<ParamField body="top" type="number" default="100">
  Maximum number of preview rows. The response is also cut off at 10,000 characters.
</ParamField>

**Example prompt**

> "Preview the data after step 2 in pipeline 4821, first 50 rows."

## `list_pipeline_step_types`

Lists the public pipeline step types and their groups. Use this to discover what types are available before calling `add_pipeline_step` or `create_pipeline`.

No input parameters. Returns a structured list of step type groups, each containing type IDs, labels, and descriptions.

**Example prompt**

> "What pipeline step types are available in Alphacast?"

---

## `get_pipeline_step_config`

Returns the configuration schema, validation rules, and AI-facing authoring examples for a specific pipeline step type. Use this to understand what `configuration` object to pass when calling `add_pipeline_step` or `edit_pipeline_step`.

<ParamField body="stepType" type="string" required>
  The step type ID (e.g. `"fetch-dataset"`, `"fetch-fred"`, `"merge"`, `"ai-transform"`, `"calculate-variable"`, `"chart-data"`, `"publish"`).
</ParamField>

**Example prompt**

> "What configuration fields does the `merge` step type accept?"

---

## `get_pipeline_formula_reference`

Returns the complete formula syntax and built-in functions reference for `calculate-variable`, `apply-formula`, and `filter-rows` pipeline steps. Covers arithmetic operators, column references (`#'Column Name'`), aggregation functions, date functions, and conditional logic.

No input parameters.

<Tip>
  In raw MCP/API formulas, reference columns as `#'Column Name'` — not the `@Column` shorthand used in the visual editor.
</Tip>

**Example prompt**

> "What formula syntax can I use in a calculate-variable step?"

---

## `create_pipeline`

Create a new pipeline, optionally with initial steps. When you include steps, Alphacast starts a run. The tool returns before the run finishes, with the run ID and any validation information. Check the result with `wait_pipeline_run`. Don't create the pipeline again to check progress.

<ParamField body="name" type="string" required>
  Pipeline name.
</ParamField>

<ParamField body="repositoryId" type="number">
  Target repository. Omit to use your default writable repository.
</ParamField>

<ParamField body="steps" type="object[]">
  Optional initial steps. Each entry has `type`, `order` (0-based), and `configuration` (a step-specific object).

  Call `get_pipeline_step_config` for the exact configuration of each type. Examples:

  - `fetch-dataset { datasetId }`
  - `fetch-yahoo { tickers, period }` — use [`search_tickers`](/mcp/tools/tickers#search_tickers) to discover symbols first
  - `fetch-fred { series }`
  - `merge { datasetId, how }` (see [Common patterns](#common-patterns) to merge two branches)
  - `transform { transformation, columns }` — built-in transformations with auto-fetched auxiliary data (USD conversion, constant prices, per capita, seasonal adjustment)
  - `ai-transform { code }` — Python with `def run(df): return df, 'log'`
  - `publish { datasetId }` or `publish { datasetName }`
</ParamField>

**Example prompt**

> "Create a pipeline named 'US inflation YoY' that fetches FRED CPIAUCSL and applies a `pc1` transformation."

<Warning>
  There is no MCP tool to undo a change or delete a pipeline. Use the pipeline editor. See [Run a pipeline](/pipelines/runs#undo-the-last-change).
</Warning>

## `add_pipeline_step`

Add a step to an existing pipeline. Alphacast saves, validates and runs the pipeline. By default the tool returns as soon as the change is saved, with the editor run ID.

<ParamField body="pipelineId" type="number" required>
  Pipeline ID.
</ParamField>

<ParamField body="type" type="string" required>
  Step type. See `list_pipeline_step_types` and `get_pipeline_step_config`.
</ParamField>

<ParamField body="order" type="number" required>
  0-based position in the pipeline. Use the next available order to append.
</ParamField>

<ParamField body="configuration" type="object" required>
  Step-specific configuration. For `calculate-variable`, reference columns as `#'Column Name'`, not the `@Column` shorthand used in the editor. For an `ai-transform` with named inputs, `inputs: [{ alias, stepId }]` must use the IDs of earlier steps.
</ParamField>

<ParamField body="waitForRun" type="boolean" default="false">
  When `true`, wait for the run to finish before returning.
</ParamField>

<ParamField body="timeoutSeconds" type="number" default="60">
  Maximum seconds to wait when `waitForRun` is `true`.
</ParamField>

**Example prompt**

> "Add an `ai-transform` step to pipeline 4821 that computes a 12-month rolling average of the `Value` column. Wait for the run and tell me how it ended."

---

## `edit_pipeline_step`

Update an existing step. Alphacast saves, validates and runs the pipeline. By default the tool returns as soon as the change is saved, with the editor run ID. Send the full configuration. `chart-data` is the exception: your changes, including partial `grapher` patches, are merged with the existing configuration. Keep its `chartId`.

<ParamField body="pipelineId" type="number" required>
  Pipeline ID.
</ParamField>

<ParamField body="stepId" type="number" required>
  Step ID to edit.
</ParamField>

<ParamField body="type" type="string" required>
  Step type — must match the existing step's type.
</ParamField>

<ParamField body="order" type="number" required>
  Step order (0-based).
</ParamField>

<ParamField body="configuration" type="object" required>
  Full updated configuration for the step.
</ParamField>

<ParamField body="waitForRun" type="boolean" default="false">
  When `true`, wait for the run to finish before returning.
</ParamField>

<ParamField body="timeoutSeconds" type="number" default="60">
  Maximum seconds to wait when `waitForRun` is `true`.
</ParamField>

**Example prompt**

> "Change step 11 in pipeline 4821 to filter dates from 2010-01-01 onwards."

---

## `delete_pipeline_step`

Remove a step from a pipeline. Alphacast validates and runs the remaining steps. Call `get_pipeline` afterwards to check step order and status.

<ParamField body="pipelineId" type="number" required>
  Pipeline ID.
</ParamField>

<ParamField body="stepId" type="number" required>
  Step ID to remove.
</ParamField>

**Example prompt**

> "Remove step 14 from pipeline 4821."

## Common patterns

**Branching and merging.** Fetch source A, optionally reshape or resample it, then `stash`. Fetch source B, then `merge` with `{ stash: true, how: 'left', columns: [{ name: 'Date', matchTo: 'Date' }] }`. When the two sources have different frequencies, resample one branch first.

**Appending.** Fetch source A, `stash`, fetch source B, then `append-dataset` with `{ stash: true }`.

**Publish.** Use `publish { datasetId }` to write into an existing dataset, or `publish { datasetName }` to create a new dataset in the pipeline's repository.
